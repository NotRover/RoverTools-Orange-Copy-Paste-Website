Contributions are welcome. Each repo has its own `CONTRIBUTING.md` with the details; this is the
short version.

## The three repos

| Repo | Stack | Package manager |
|------|-------|-----------------|
| [Client](https://github.com/NotRover/RoverTools-Smart-Clipboard-App-RUST) | React + TypeScript + Vite, Tauri 2 / Rust | bun |
| [Backend](https://github.com/NotRover/RoverTools-Smart-Clipboard-App-Backend) | Python 3.14, FastAPI | uv |
| [Website](https://github.com/NotRover/RoverTools-OrangeCP-Website) | Astro + Starlight | bun |

The client lives directly in the parent repo; the backend and website are submodules with their
own repos. Keep each change scoped to one repo.

## Setup and checks

**Client** (from `orange-copy-paste-clipboard-app-rust/`):

```bash
bun install
bun run tauri dev        # full app
bun run build            # typecheck + build the frontend
cd src-tauri && cargo check
```

**Backend** (from the backend repo, via uv):

```bash
uv run uvicorn src.main:app --reload   # or: docker-compose up
uv run ruff check src
uv run ty check src
uv run pytest
```

**Website** (from the website repo):

```bash
bun install
bun run dev
bun run build            # also the verification step
```

Run the smallest check set that covers what you touched, and say so in your pull request if you
could not run something (full end-to-end sync needs a live backend, a Supabase project, and two
accounts).

## Opening a change

- Work on a branch, and open the pull request against that repo's `main`.
- A change that crosses the client/backend wire is a change to both repos. The wire contract has
  one home, the [backend architecture doc](https://github.com/NotRover/RoverTools-Smart-Clipboard-App-Backend/blob/main/docs/architecture.md);
  update it in the same change.
- Never re-implement encryption, key handling, or merge logic on the TypeScript side. The Rust
  core owns all of it.
- Commit messages are `type(scope): subject` in lowercase, with a few single-line bullets on what
  changed and why.

See each repo's `CONTRIBUTING.md`, `SECURITY.md`, and `CODE_OF_CONDUCT.md` for the full policy.
